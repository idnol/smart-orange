# Імпорт заявок (CSV → MySQL)

Сторінка імпорту заявок на чистому PHP 8 + PDO + MySQL 8. Наданий файл (100 000 рядків, ~26 МБ)
повністю записується в БД при **стандартних** налаштуваннях PHP: `max_execution_time=30`,
`upload_max_filesize=2M`, `post_max_size=8M` (ліміти навмисно не піднімаються).

## Запуск

```bash
docker compose up -d --build
```

Відкрити http://localhost:8088, вибрати CSV і натиснути «Імпортувати».
Структура БД — [`schema.sql`](schema.sql) (підхоплюється MySQL-контейнером автоматично).
MySQL доступний на `localhost:3307` (`leads` / `leads`, БД `leads`).

Без Docker: імпортувати `schema.sql`, задати `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASS`
(або змінити [`config.php`](config.php)), document root — `public/`, каталог `storage/uploads` має бути доступний на запис.

## Як це працює

1. **Завантаження шматками.** Файл 26 МБ не пройде звичайним POST (ліміт 2 МБ / 8 МБ), тому браузер
   ріже його `File.slice()` по 1 МБ і надсилає послідовно на `upload.php`; сервер дописує їх у
   `storage/uploads/{id}.csv`. Повторна відправка шматка безпечна (запис іде з переданого offset).
2. **Покрокова обробка.** `process.php` за один запит обробляє до 10 000 рядків (або до 10 с):
   `fseek` на збережений `byte_offset` → `fgetcsv` → пакетні `INSERT` по 500 рядків. Браузер викликає
   кроки, доки статус не стане `done`. Один крок триває ~0,35 с, весь файл — ~6 с разом із завантаженням.
3. **Атомарність і відновлення.** Вставка рядків і оновлення `byte_offset` виконуються в одній
   транзакції (запис імпорту заблоковано `SELECT … FOR UPDATE`). `UNIQUE(import_id, line_no)` +
   `INSERT IGNORE` гарантують, що повтор кроку після обриву не створить дублів.

## Особливості даних

Критерій — записати **всі** рядки, тому жоден рядок не відкидається: сирі значення зберігаються,
нормалізовані поля при помилці стають `NULL`, а рядок позначається `is_valid = 0` з переліком полів у `errors`.

| Проблема у файлі | Рішення |
|---|---|
| 205 повторів `external_id` з різними даними | `external_id` — звичайний індекс, не `UNIQUE` |
| Бюджет з нерозривним пробілом (`23 700`), 20 тис. порожніх | лишаються тільки цифри → `INT`, порожні → `NULL` |
| Телефони `#ERROR!`, `12345`, `380`, `501234` | `phone_raw` як є, `phone` = `+380XXXXXXXXX` або `NULL` |
| Email-и `a@@ukr.net`, `...gmail.com`, `@icloud.com`, порожні | `email_raw` як є, `email` — лише валідний (`FILTER_VALIDATE_EMAIL`) |
| Порожні ім'я, менеджер, коментар, utm, дата контакту | `NULL` |

Колонки зіставляються за назвами із заголовка (порядок не важливий, BOM ігнорується).
Якщо обов'язкових колонок немає — імпорт отримує статус `failed` з описом помилки.

Результат для наданого файлу: **100 000** рядків, з них 97 691 валідний і 2 309 з помилками.

## Структура

```
schema.sql              структура БД (imports, leads)
config.php              налаштування (БД, розмір шматка, ліміти кроку)
src/Importer.php        прийом шматків і покрокова обробка
src/LeadNormalizer.php  валідація та нормалізація рядка
public/index.php        сторінка імпорту
public/upload.php       прийом шматка файлу
public/process.php      один крок імпорту
public/app.js           завантаження та цикл кроків з прогрес-баром
```
